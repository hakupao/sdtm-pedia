## 0. 一句话

`both` 档的检索侧代价已量出 (cards −5.21pt, 悬着未付) 但**答题侧一个字都没测**, 而答题侧的
尺子本身已被 U2 实测为不可用 (仪器全距 6.25pt > 声称效应 2.8pt)。本单元先把答题侧仪器建到
"能给出逐题稳定性 + 噪声分解"的程度, 再用它量 `both` 两个方向的答题侧代价, 并把触发率从
演绎升级为观测。**只量不改**: router / 席位 / gold / 阈值 / 生产代码一律不动。

## 1. 现状与动机

1. **判库修法线的真前置** (U3 §9-2, 审查方机制层结论): 全套路由判据把 `both` 当「更宽但
   安全」。若答题侧实测 `both` 便宜, 正确动作是**放宽 router 而非磨尖它**, U3 FAIL 收口的
   修法线可能失去必要性。这个判断没做之前, 判库欠账重启不接单。
2. **检索侧尺子已到头** (both_ruler §2.4): doc-gold source_recall 对 B1/B3 是结构恒等,
   换题集换工作点都测不出 doc 加权的增益; **`both` 的效应只能在答题侧显形**。
3. **答题侧仪器不可用是实测事实** (U2 §5-2/3/4): 全距 6.25pt (含两对命令逐字相同的臂),
   空臂 n=1 是点估计, judge 落点是粗网格 {0, .3333, .5, .6667, .75, .8, 1},
   地板到阈值空隙 0.61pt < 单题步长 0.69pt。**任何 3pt 级结论都先要有仪器** (U2 §8-1)。
4. **触发率现状**: eval 题集代理已测 (cards 5/51 · doc 0/30, LLM 判非兜底, 三遍一致);
   生产日志 `logs/api.launchd.log` 仅 7 条 `federation_routed` (2026-08-04~07, 0 次 both,
   全 fallback=False) ⇒ **线上真实触发率无数据可言, 本单元不假装能测它**。
   run 产物不记逐题 routed/fallback (both_ruler §5-8/§5-11 两条仪器缺口), 「哪题去了哪档」
   至今靠演绎。

## 2. 单元边界

**做**: ① 答题侧仪器 (同配置重复 + judge 重判探针 + 双向对照); ② `both` vs `study` 两个
方向 (cards 48 计分题 / doc 30 题) 的答题侧代价, 逐题配对判定; ③ run 产物补逐题
`routed`+`fallback` 观测字段, auto 档触发分布从演绎升级为观测。

**不做 (逐条写死)**:
- **收益侧出局** (用户裁定 2026-08-16): 不建跨库题集, 不测 `both` 对跨库问题的收益。
  ⇒ 收口文件必须写: **本单元不能论证「both 不值得」** (both_ruler §5-10 的误用警告)。
- `server/` 生产代码**除下述一处零行为观测属性外一律不动** (修正案 1, 2026-08-16, 理由见
  §2 代码改动面 1); 不动 router prompt (U3 §9-3/4 前置未满足); 不动席位配置
  (`doc_seats` / `k_each`); 不动任何 gold / 阈值 / `score_run` fatal 定义 (U3 §9-6)。
- 不改答题侧 fact gold (与 U1/U2 数字可比性优先; 粗网格问题记为已知限制, 不在本单元修)。
- 不测线上触发率 (n=7, 无数据; 只照录事实)。

**代码改动面 (各带测试)**:
1. `run_eval` 产物 `results[*]` 补 `routed` + `routed_fallback` 字段 (观测字段, 零行为改动)。
   **修正案 1**: 这需要 `server/federation.py` 加一个观测属性 `last_route_fallback`

   (eval 自己调 `route_corpus` 再强制档) 被否: 引入 eval/生产两路径漂移风险, 正是
   `make_docs_engine` 同源闸要防的病。
2. judge 重判工具 (读已落盘 run json, 对存量 (题, 答案, facts) 重跑 judge, 不重新答题)。

   合成 fixture 测试** — U3 §6-10 的教训: 判定脚本零测试 = 结论可翻不留痕。

## 3. 测量矩阵与仪器

### 3.1 矩阵 (4 配置 × 3 遍, 同参数重跑)

| 配置 | 题集 | 档 | 席位 (cdisc/cards/doc) |
|---|---|---|---|
| M1 | cards 51 行/48 计分 | `--corpus study` | 0 / 15 / 8 |
| M2 | cards 同上 | `--corpus both` | 8 / 8 / 8 |
| M3 | doc 30 题 | `--corpus study` | 0 / 15 / 8 |
| M4 | doc 30 题 | `--corpus both` | 8 / 8 / 8 |

- 全部 `--study-docs` (N=8) + `--judge`, 答题模型 = 生产默认 (Bedrock jp sonnet),
  judge 模型 = U2 同款 (deepseek-chat), 温度同 U2 (plan 落地时从 U2 的答题臂命令工件取
  字面值, 不许凭记忆写)。**单模型单温度, 记为已知限制。**
- **同配置内 3 遍互比 = 空臂/ON-ON 的推广** (同配置差异全是噪声); 跨配置才是效应。
- M1 与 U2 的 ON 臂 (0.8542/0.8819) 同配置, 并排报告作历史锚点; ⚠ 不设 exact-match 校准闸
  — 答题侧非确定, 期望逐位复现就是把噪声当回归。
- 检索非确定性 (U2 §5-1, embedding API) 由 3 遍纪律覆盖。

### 3.2 仪器读数 (先于效应, 从矩阵自身提取)

- **逐题稳定性**: 题 q 在配置 M 下「稳定」 iff 3 遍 judge 分完全相同。每配置报
  不稳定题数 + id 清单。
- **judge 重判探针**: 取 M2 r1 与 M4 r1 两份已落盘产物各重判 1 遍 (不重新答题),
  报逐题同分率 ⇒ 把「judge 自身噪声」从「答题噪声」里分解出来。
- **双向对照** (U2 条款 4 同款): 阳性 / 阴性对照两个题集各跑一次。判据沿用 U2 已冻结的
  阈值 (修正案 2: 初稿写的 1.0000/0.0000 是 U2 的**实测值**不是**判据**, 拿实测当判据会让
  单次 judge 抖动误触发停机): 阳性 **≥ 0.80** 且 阴性 **≤ 0.20**; U2 实测 1.0000/0.0000,
  期望复现, 实值照录。

## 5. 判定规则 (先于数据写死, 跑批后一字不改)

### 5.1 仪器闸 (I)

| # | 闸 | 判据 | 不过的后果 |
|---|---|---|---|
| I1 | judge 重判 | 两份探针逐题同分率均 ≥ 95% | judge 噪声主导: E 判定降级 advisory (报数字, 不写「便宜/贵」结论词) |
| I2 | 逐题稳定性 | 每配置不稳定题 ≤ 15% 计分题 (cards ≤7/48, doc ≤4/30) | **仪器不可用, 自毁**: 本单元不下 both 结论, 收口 = 仪器读数 + 「下一步是修仪器不是测量」 |
| I3 | 双向对照 | 阳性 ≥ 0.80 且 阴性 ≤ 0.20 (两题集, U2 冻结判据) | **停下上报**, 不解读任何双臂数字 |

### 5.2 效应规则 (E) — 逐题配对, 双向对称

- **E1 (已确证代价/收益)**: 题 q 计入 iff 在该方向的两个配置下**都稳定**且两侧分数不同。
  study 分 > both 分 ⇒ 计入**已确证代价**; study 分 < both 分 ⇒ 计入**已确证收益**。
  两个清单都必须报 (U3 §6-6 的教训: 单向口径既漏真回归又杀真改善)。
  代价/收益额 = Σ逐题差 / 计分题数, 附全部题号。
- **E2 (判定)**: cards 方向与 doc 方向的已确证代价**均为 0** ⇒ 「both 在此尺上便宜」
  (收益不阻塞该判定); 任一方向 > 0 ⇒ 报数额与题号, **不得**加「both 不值得」类结论。
- **E3 (定向传导分析)**: 检索侧 4 道脆弱题无论稳定与否逐题点名 (检索丢分是否传导为答题丢分;
  `st01_v2_q14` 检索 gold 全丢是唯一归零题, 它的答题侧走向是本单元最有信息量的单点)。
- **E4 (不可判池)**: 任一侧不稳定的题列入「不可判」清单; 若 4 道脆弱题落入其中, 点名说明。
  不可判题上**不许下任何结论**。

### 5.3 自毁与修改纪律

1. 任何 I 闸触发 ⇒ 按其后果列执行 + 失败归档 (规则 B) + 停下上报用户, 不许静默绕过。
2. 看过任何跨配置数字之后, I/E 阈值与判据**一字不许改**; 发现规则本身有缺陷只能记录+上报,
   当轮不修 (U1/U2/U3 三轮的同一条纪律)。
3. 判定由 `eval/u5_verdict.py` 确定性给出, 人不许手算改判。

## 8. 本单元明确不能证明什么

- **不能**证明「both 不值得」— 收益侧未测 (单库题集, 用户裁定出局)
- **不能**证明换答题模型 / 换温度 / 换 judge 下结论成立 — 单模型单温度单 judge
- **不能**证明线上触发率 — 生产样本 n=7, eval 题集分布 ≠ 线上流量
- **不能**证明判库正确性有任何变化 — 本单元不动 router
- **不能**证明 N=8 / 现行席位配置最优 — 只测现行配置 (k=15, doc_seats=8)
- **不能**在不可判池 (不稳定题) 上下任何结论
- 若 E2 判「便宜」: 只是**在此尺上** (judge 粗网格 + fact gold 现状) 的便宜, 放宽 router
  本身仍是**新单元**, 且须自带路由闸全套判据 (U3 存续的 253 题 + 六条条款)
