# SP7 设计 — KG 查看器 UX 重构(确定性布局 + 精密仪器美学)

> 状态: **设计待评审** (2026-07-24)
> 来源: 本设计由一次 brainstorm 收敛而来(用户七项决策见 §1.3)。
> 上游: SP6 网状查看器 `scripts/build_kg_viewer.py` / `kg_viewer.html`(现有产物) · [[SP1 meta.yaml]](硬结构真源) · `data/meta/implicit_relations.json`(advisory 软层)
> 硬约束: 产物仍是**零依赖 · 离线 · 单 HTML**(不引外部字体/CDN);类的 CVD-safe 配色(--c1..--c8)与明暗双主题保留;软层永不改动 meta.yaml。

## 1. 背景与目标

### 1.1 现状 / 痛点
现有 `kg_viewer.html`(SP6 收官产物,由 `build_kg_viewer.py` 的 `TEMPLATE` 生成)采用**力导向物理模拟**驱动全部四视图。用户核心抱怨:**"点一下到处飞到处弹"**。定位到两处病根:
1. **常驻物理**: `frame()` 用 rAF 持续跑力模拟(斥力 REP + 弹簧 SPRING + 重力 GRAV),节点永远在抖。
2. **每次交互全量重排**: 视图切换 / explore 展开都走 `build()` → `seed()`(phyllotaxis 螺旋重新播种)+ `alpha=1`,整张图"炸开"重新收敛。位置**不可预测**(不利"查")、**一直在动**(不利"展")、**点击就乱弹**(不利"探")。

### 1.2 目标
把查看器从「力导向 + 每次重排」重构为「**每视图确定性布局 + 缓动补间过渡 + 无常驻物理**」,并把视觉语言提升为有鲜明性格的**精密仪器**美学。同时服务三类使用者: **查**(带目标查具体关系)、**探**(无目标逛发现关联)、**展**(给同事/客户/面试展示)。

### 1.3 已决策(brainstorm, 2026-07-24)
| # | 维度 | 决策 |
|---|---|---|
| 1 | 改动范围 | **较大重构 UX**(非仅止血动效) |
| 2 | 主要场景 | **查 / 探 / 展 三者兼顾** |
| 3 | 布局范式 | **B — 确定性布局 + 补间过渡**,删除常驻物理(唯一能根治"到处飞") |
| 4 | 视图结构 | **保留 4 视图**(结构总览 / 域钻取 / 码表影响 / 网状探索),只换各自内部布局,心智模型不变 |
| 5 | 视觉野心 | **鲜明的性格**(不止精修) |
| 6 | 美学方向 | **方向 1 · 精密仪器**(暗色优先,工程/仪表盘质感);可借编辑级排版做标题层次 |
| 7 | Explore 展开语义 | **锚定累积**(保留"累积成网",但展开时已有节点全锁死,只新邻居淡入;乱了可手动"整理") |

### 1.4 Non-goals(YAGNI)
- 不改数据层(meta.yaml / implicit_relations.json 不动),不改挖掘管线。
- 不改视图数量与语义边界(4 视图不增减不合并)。
- 不引外部字体/库/纹理资源(离线单文件铁律);性格从系统字体栈驾驭 + 配色 + 间距 + SVG 细节 + 微交互榨出。
- 不做 RAG 侧改动(保留"深入解释"按钮及其离线优雅降级)。
- 不追求把 explore 变成会自动整理的智能布局;整理是**用户手动触发**的一次补间。

## 2. 架构总览

**源码拆分(建议)**: 现有单文件 `TEMPLATE` 字符串已偏大,重构后 CSS/JS 显著膨胀。建议把源码拆为独立可维护文件,build 时内联成单文件产物:

```
sdtm-rag/viewer/
  ├── template.html   (骨架 + SVG defs + 占位符 __STYLE__ / __APP__ / __DATA__)
  ├── style.css       (精密仪器视觉系统)
  └── app.js          (布局函数 + 补间引擎 + 交互)
        │  build_kg_viewer.py: build_data() 注数据 + 内联 css/js
        ▼
sdtm-rag/kg_viewer.html   (零依赖 · 离线 · 单 HTML, 与现在一致)
```
产物形态、数据来源(`extract_graph(load_meta(meta.yaml))` + `implicit_relations.json`)、生成命令(`.venv/bin/python scripts/build_kg_viewer.py`)均不变。**绝不直接手改 `kg_viewer.html`**——它是生成物。

> 若评审否决拆分,退化方案: 一切仍写在 `build_kg_viewer.py` 的 `TEMPLATE` 内(功能等价,仅可维护性差)。

## 3. 布局设计 — 四视图确定性布局

通则: 每个布局是**纯函数** `layout(view) → 每节点固定 (x,y)`,相同输入永远同一结果(可预测、可测试)。不含随机、不含时间。密度处理内建避重叠,标签可读。

### 3.1 结构总览 · 簇状放射星座 (vOverview)
- 8 个类枢纽固定排在半径 `R_hub` 的环上,角度按 `CLASS_ORDER` 均匀分布(起点正上 -π/2)。
- 每个类的域(按 code 字典序)排成一个**朝外的楔形簇**: 以该枢纽的外向径向为中心轴,在有界角宽内分 `ceil(k/perRing)` 环铺开(k 大的类如 Findings 多环容纳)。
- 枢纽 = 大圆带标签;域 = 小圆,标签为域码(等宽)。边 = 域→枢纽的短径向辐。
- 结果: **星座每次一模一样**,用户可记住"每个类住在哪"。

### 3.2 域钻取 · 左→右分层轨道 (vDomain)
- 三列固定 x: 域(x0) → 变量(x1) → 码表(x2),像 schema 图,最利"查/读"。
- 变量: 竖直等距堆叠,按 meta 出现序(≈role/CDISC 序);数量 > 阈值(默认 24)则拆两子列,约束总高。
- 码表: 去重后堆在 x2,y 取"引用它的变量们"的质心邻近值(短边),再做去重叠。
- 域节点对齐变量列竖直居中。边: 域→变量、变量→码表(直线或水平缓曲连接线)。

### 3.3 码表影响 · 轮辐 (vImpact)
- 码表居中(大);波及域按 `CLASS_ORDER` 再按 code 排序后,**同类角度相邻**地均匀排在环上(同类形成着色弧)。
- 域多则用双同心环。结果: 扫一眼即知"这码表触达哪 N 个域、集中在哪些类"。

### 3.4 网状探索 · 自我中心雷达 + 锚定累积 (vExplore)
- **初始**: 种子居中 (0,0)。其邻居的环被切成 4 个角度扇区,按关系层归属: 硬关联 / 数据流 / 显式链接 / 共现;每扇区内按置信度降序在半径 `R1` 等角排布。环"可读": 看角度就知关系类型。
- **锚定累积展开**: 点已在图上的节点 P → 把 P 的**尚未显示**邻居放到 P 周围的空角度槽(在半径 r 探测空位避开既有节点),缓动淡入;**已有节点位置全部不变**。保留 SP6 的 `EXPLORE_CAP=40` 与展开优先级(硬边邻居 > 推断邻居按置信度)。
- **"整理"按钮**: 用户手动触发,对当前显示集重算一版确定性布局(按到种子的 BFS 深度分环 + 扇区归类),全体补间就位。取代原"⏸ 布局"钮(无物理后失去意义)。
- 边样式沿用 SP6 图层编码(硬=灰实、数据流=蓝实+箭头、显式链接=绿虚、共现=紫点);图层开关保留。

## 4. 过渡 / 动画模型(根治"到处飞")

- **删除常驻物理**: 退役 `tick()` 力计算、`frame()` 常驻 rAF 循环、`seed()` 螺旋播种、REP/REST/SPRING/GRAV/DAMP/alpha 等常数。
- **补间引擎**(新): `animate(targets, {duration:380, easing:easeOutCubic})` —— 捕获每节点起点 (x,y),按缓动插值到目标,逐帧更新 `<g transform>` 并调 `draw()` 刷新边,跑完即停。全程无物理。
- **新节点**: 从父节点位置(或目标位 + scale 0/opacity 0)淡入+微缩放。**移除节点**: opacity→0 后摘除。
- **拖拽**: 直接写节点 (x,y),边随 `draw()` 跟随,**不扰动其他节点**;松手后**停在落点**(坐标持久,直到下次布局/整理)。
- **缩放/平移**: 保留现有 `T={k,x,y}` 逻辑不变。

## 5. 视觉系统 · 精密仪器

在保留 `--c1..--c8`(CVD-safe 类配色)与明暗双主题的前提下,新增/改造:
- **暗色优先**: 默认跟随系统偏好(亮色用户仍得亮色),但设计以**暗色为主基调**打磨到位,亮色作一等公民适配;主题钮保留。
- **发丝网格背景**: SVG 平面铺极低对比网格/点阵(新增 `--grid`),边缘淡出 —— "工程坐标纸"暗示。随缩放平移。
- **信号色**(新增 `--signal`, 青或琥珀实现时定,须落在 8 类色之外避免语义撞车): 仅用于焦点/选中/激活态。
- **字体**: chrome 用系统 UI 栈;**所有码值/计数/坐标用等宽**(`ui-monospace`),数字 tabular;小标题小型大写字 + 收紧字距。
- **节点**: 几何精准、1px 利落描边;hover/选中给一圈细"标线环"(reticle)强化焦点,而非仅把其余调暗。
- **边**: 发丝矢量,高亮时提亮 + 微辉光(`filter`/叠色);有向箭头 marker 精修。
- **面板/图例/工具栏**: 仪表盘质感——细边框 + 顶部一道高光"面板棱",减重毛玻璃 backdrop-blur;分段控件激活态用信号色;图例做成干净 key,等宽标签;`#count` 作"仪表读数"样式。

## 6. 交互打磨(Inspect 面板 & 搜索 & 联动)
- Inspect 面板: 字号层次重排、码值等宽、发丝分隔线、sticky 头 + 关闭钮;**保留** RAG"深入解释"(`fetch(:8000/api/health)` 探活,离线自动隐藏)与"点推断边→证据弹窗"(引文 + 来源:行 + 置信 + 核验)。
- 搜索: 命中高亮/非命中淡出保留;可选把首个命中居中(缩放平移补间)。
- hover 联动: 邻居保留、非邻居淡出的逻辑保留,叠加"标线环"。

## 8. 测试与核验(Tier 2 流程)

本单元是**视觉/交互重构**,以浏览器实证为主,辅以确定性检查:
- **确定性检查**: 布局函数纯函数性——同输入两次调用坐标一致(可在 `app.js` 内加 dev 断言,或建一 Node 小测跑布局导出比对)。重生成后 `kg_viewer.html` 能开、无 JS 报错(console 干净)。
- **浏览器核验(主)**: 起本地静态服务,`chrome-devtools`/`claude-in-chrome` 逐视图 + 明暗双主题截图。**重点验收**: (a) 视图切换/展开**不炸开**、位置稳定;(b) 拖拽只动单点;(c) 四视图布局符合 §3;(d) 精密仪器视觉在明暗下都成立;(e) RAG 按钮在线/离线正确。
- **规则 D 审阅隔离**: executor 写码(可 opus),**另一个 subagent**(code-reviewer/verifier,不同 session)独立看截图做业务判定;不自审。
- **规则 A 抽检**: 本重构非内容压缩/改写,Rule A 的 N 样本内容抽检不直接适用;以**独立视觉核验 + console 干净**替代其"独立样本"精神,留证 `evidence/checkpoints/kg_viewer_ux_redesign.md`。
- **规则 B 失败归档**: 被否的布局/视觉 attempt 归档 `failures/`,不删。
- **Tier 2 产物**: PLAN.md / `_progress.json` / evidence/ / failures/ / RETROSPECTIVE.md(收尾前必写,规则 C 三段)。

## 9. 成功标准(验收)

1. 四视图任意切换、explore 任意展开,**无"炸开/乱弹"**,已有节点位置稳定,过渡为一致的缓动补间。
2. 每个视图布局确定(同数据每次同构图),符合 §3 的四种形态;拖拽只动被拖节点。
3. 视觉呈现**精密仪器**性格(网格/等宽码值/标线环/仪表盘面板/信号色),明暗双主题皆成立且 CVD-safe 类色保留。
4. 产物仍为零依赖离线单 HTML;RAG 在线/离线行为、图层开关、证据弹窗等 SP6 既有能力无回归。
5. 规则 D 独立核验 PASS,evidence 留证;console 无报错。

## 10. 风险与开放问题(实现计划期定)
- 信号色最终色相(青 vs 琥珀)与在明暗下的对比达标。
- 域钻取里超多变量(40+)的分列阈值与连线可读性。
- explore 锚定累积多次展开后的连线交叉(靠"整理"兜底)——手感需实测调。
- 补间时长/缓动曲线手感(380ms/easeOutCubic 为起点)。
- 源码拆分后 build 内联的实现细节(占位符替换 vs 读文件拼接)。
- 放射星座在最大类(Findings)下的楔形角宽/环数,避免簇间视觉粘连。
