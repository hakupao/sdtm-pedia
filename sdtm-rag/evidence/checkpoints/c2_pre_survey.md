## 2. 结论集 (三个, 不是两个)

| 结论 | 含义 |

| **RELATION** | 增量是**字段之间的关系**, 正确产物是结构化关系 (catalog / KG 直查), **不是 chunk** |

## 3. 抽样方法 (先写死, 不许看完再选)

**主样本 (所有比例数字只从它算)**: 每份**等距 12 页**, 页号 = `floor(i * N / 12) + 1`,
`i = 0..11`, `N` = 总页数。确定性, 无随机种子, 可复算。

- C2-a (N=933): 1, 78, 156, 234, 311, 389, 467, 544, 622, 700, 777, 855
- C2-b (N=212): 1, 18, 36, 54, 71, 89, 107, 124, 142, 160, 177, 195

**补样 (形态用, 最多 8 页/份)**: 允许额外看少量页去覆盖 kickoff §C2 条件 2 点名的四类形态
(表单 / 表格 / 勾选框 / 跳转逻辑)。**补样页不进任何比例统计**, 只用于形态描述与写问题样例。
补样页号必须在报告里列出。

## 4. 减法的操作定义

对主样本每一页, 用 `pdftotext -layout` 取文本, 逐 token 对照 `data/study/st01/catalog.json`
的四个池: `items` (959) / `forms` (21) / `codelists` (643) / `ledger` (3508)。分三类:

1. **catalog 命中** — token 能在上述任一池里找到 (OID / label / codelist 值)
2. **版面结构元素** — 页眉页脚 / 页码 / 表单标题 / 编号 / 分隔符
3. **未命中残余** — 既不在 catalog 也不是版面元素

**`catalog_coverage` = 类 1 字符数 / (类 1 + 类 3) 字符数**, 逐份报告。
类 2 排除在分母外并**在报告里写明排除了多少** (硬规矩 19: 引用闸的绿灯必须写清它看不见什么)。

**减法产物 = 类 3 的内容清单** —— 这才是"增量"。本勘察的核心是这一项, 不是看版面。

## 5. 判据与自毁条款

**主判据 (每份独立)**:

- 从减法结果写出**可检验问题样例**: 每道须标注 ① 答案依赖哪个信息项 ② 该信息项在 catalog
  四池中的检索结果 (必须**程序化**给出"不存在"的证据, 不许用"我觉得卡片答不出")。
- **≥5 道**通过上述检验 → 该份进下一步 (5-10 页价值探针);
- **<5 道** → **该份判 DROP**, 写进本 checkpoint 归档, 不留尾巴。

**「真实工作里会问」由用户裁定, 我不自判。** 我只提交候选样例与其 catalog 检索证据;
"这道题现实中会不会有人问"这一层留白给用户勾选。理由: 自己出题自己判会重演本仓已多次
出现的"尺子饱和"闭环。

**形态判据**: 若通过检验的样例中 **≥3/5 的答案依赖"字段之间的关系"** (同表单归属 /
访视安排 / 跳转条件 / 表单内分组) 而非字段本身的内容 → 结论取 **RELATION** 而非 CHUNK。

**自毁条款**:

- **S1**: 某份拿不到 ≥5 道 → 该份 DROP。
- **S2**: 两份都拿不到 → **Plan C 整体判不做**, C2 从 kickoff §0′ 候选表移除。
- **S3 (防凑数)**: 若某份 `catalog_coverage ≥ 95%`, 则该份的门槛从 ≥5 **提高到 ≥8**,
  且报告须显著标注「增量稀薄」。理由: 覆盖率越高, "凑够 5 道"越可能是我在硬找。
- **S4**: 若主样本 12 页里有 **≥3 页** `pdftotext` 抽不出有效文本 (扫描件/纯图),
  则本勘察方法本身失效 → 停止, 报告"需要 OCR 才能评估", **不许**用剩余页硬给结论。

### 7-7 已知限制 (必须与结论并排声明)

1. **`catalog_coverage` 的口径**: 类2 版面元素 (页眉页脚/页码/纯项号) **排除在分母外**;
   匹配是**规范化后子串包含** (NFKC + 去空白 + 小写), 不是语义等价 —— 它证明「字面在」,
   不证明「检索得到」。硬规矩 19: 这个绿灯看不见语义差异。
2. **两次方法伪影, 均由本人自查发现并修正, 记录在此**: ① 首版按**整行**比对, 多列版面被拼成
   一行导致假残余 (a 88.7% / b 82.1% 是**错的数**); ② 二版 `#NN` 只剥了尾部, 而它是**前缀**,
   又产生假残余 (a 61.4% / b 86.7% 也是**错的数**)。**只有 §7-2 的数字有效。**
   这是硬规矩 17b (关键数字用非自洽写法复算) 的又一次实证。
3. **预登记 §3 的 C2-a 页号枚举有 5 处 off-by-one** (311/544/622/777/855 应为 312/545/623/778/856)。
   **公式 `floor(i*N/12)+1` 为准, 脚本按公式执行**; 枚举是转写笔误, 不影响抽样确定性。
   C2-b 的 12 个页号枚举与公式**逐位一致**。
4. **全量普查超出预登记范围**。预登记只要求 12 页主样本, 我另做了 1,145 页全量。这是**加证据**,
   §7-2 已把两组数并列并标明哪组是预登记的。全量与样本同向, 无冲突。
5. **事件计划表的解析未做逐字保真验证**。§7-3 的「13 个事件组」出自一次性脚本的启发式切分,
   **若进入 RELATION 实现单元, 必须重做并配 C1 级别的逐字保真闸**。本勘察不为该数字背书。
6. **未做**: OCR、语义抽出、切分器、任何生产改动、任何 LLM 调用。全程零配额。
7. **C2-b ⊄ C2-a**: b 的实质内容行 4,364 行中 3,233 行 (74.1%) 在 a 全文逐字出现; 未重合的
