# C1 L1 修复 — 卷首覆盖缺口 + 全文覆盖闸 (2026-08-26)

> 上游: `study_c1_doc_sections.md` 已知限制 **L1** ("首锚点之前的内容不属于任何 chunk")
> 数据红线: 本文件进 git, 故只含数字/页码/形态描述, **零真名零正文**

## 0. 一句话结论

L1 的 66,200 字符缺口里, **3/4 是目录 (49,320), 按 C1 原判与用户裁定维持排除**;
真正的实体缺口 **16,880 字符 (全文 6.99%)** 已补齐为 **11 个 chunk**
(`study_st01_docs` 114 → **125**)。同时修掉**根因**: 完备性闸的口径原本是"首锚点行起",
对首锚点之前的区域**天然免疫** —— 不修闸, 同类盲区会在新位置复发。

## 1. 缺口的精确构成 (本轮独立复算, 与 L1 记录逐位吻合)

| 区段 | 字符 | 处置 |
|---|---|---|
| 卷首 p1–10 | 16,302 | **补** (每页一个 chunk) |
| 目录 p11–16 | 49,320 | **维持排除** (用户 2026-08-26 裁定) |
| 首锚点页 p17 前段 | 578 | **补** (半页 chunk) |
| 合计 | **66,200** = 全文 27.42% | 实补 **16,880** = 6.99% |

首锚点 = p17 的 `2.1`; 未覆盖字符数由 `full.find(sections[0].heading_line)` 直接得出 = 66,200。

**目录为什么不入库**: 目录的每一条都是某个真实章节标题的**重复**, 而那些标题本身已在
114 个编号 chunk 里; 命中目录只会返回一块"只有点线和页码"的东西, 还要和正文抢检索名额。

## 2. 根因与闸的修复 (本单元的核心)

`assert_partition_complete` 的 docstring 原文: "必须逐字等于**首锚点行起**的全文"。
⇒ 首锚点**之前**的 66,200 字符不在它的口径内, 所以 C1 那轮三把闸**全绿而缺口存在**
(L1 自己写着: "不得把闸绿读成内容都能检索到")。

新增 `assert_full_coverage(pages, sections, excluded_pages)`: 口径改为**全文减去显式
声明的排除页**。排除页必须由调用方传入且有形态依据, **不接受"没覆盖到就算排除"这种
事后追认** —— 那等于把闸的口径交给缺陷自己定义。

## 3. 目录识别: 形态判据, 不是硬编码页号

页号写死后换一份 PDF 就会静默排除掉真实正文, 而闸照样绿。故用两条合取判据:
① 编号行 ≥ 8 ② 点线行 ≥ 3 (`\.{10,}` / `・{10,}` / `…{3,}`)。

**全 113 页实测**: 只有 p11–16 这 6 页满足 ① (正文页最多 2 条编号行); 这 6 页各有
**25–46 条点线行**, 而 **107 个正文页点线行恒为 0**。两条判据各自都已能分开, 取合取是
为了让"某页恰好排版成多列数字表"也不会被误判成目录。

## 4. 卷首为什么按页切

真实文档 p1–10 实测 **编号行 0 条、可识别标题 0 条** —— 锚点切分器在这里无处下手。
页是抽取器本来的单位 (`pdftotext -layout -f N -l N` 逐页)。token 实测: 单页
**169–1,907**, 远低于 8,191 上限; **整块则是 10,034, 超限**。编号用 `front{页号:02d}`,
与编号节的命名空间不相交, 不污染 `check_numbering` 的编号序列。

## 6. 已知限制

1. ⚠ **"补上了"是覆盖口径, 不是"能答出来"口径** —— doc 侧 30 题 gold 全部出自编号
   章节, **没有任何一道题在考卷首内容**。本轮的零回归只证明新块**没有挤占**既有检索,
   **不证明**它们检索得到或有用。要证后者需要针对卷首出题, 本轮未做。
2. 目录 49,320 字符仍不可检索 (用户裁定)。若将来出现"某节在第几页"这类问法, 需重开。
3. 卷首按页切**可能切断跨页内容** —— 临床试验计划书的概要 (synopsis) 常跨 p4–9 连续
   排版, 按页切会把它分到多个 chunk。本轮未评估该切法对语义完整性的影响 (与 C1 的
   L6"疑似切断表格"同族)。
4. **`docs/` 目录指纹变了**: `0f13797f1871…` → `1d2bc9ebe466…`。U1 checkpoint §7 复跑
   命令里那条 `shasum` 断言**将不再匹配** —— 那是本次改动的预期结果, 不是缺陷。
5. C1 的 **L9 仍未解决**: PDF 文本层是否忠于版面, 本轨手段无法证伪 (参照物同为
   `pdftotext`)。本轮补的是"文本层里已有但没进 chunk"的部分, 对 L9 无改善。
6. 目录形态判据的阈值 (8 / 3) 在**这一份**文档上验证过 (6/113 页命中, 分离干净),
   对其他 PDF 的泛化未测。
