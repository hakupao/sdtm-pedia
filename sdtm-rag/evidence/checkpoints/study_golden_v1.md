## 2. 两轮独立审阅的作用 (规则 D 有效性记录)

两轮均判 REVISE, 且**每轮都抓到出题人自查漏掉的硬伤**:

| 轮次 | 级别 | 抓到的问题 (结构描述) |
|---|---|---|
| 一轮 (critic, 全量 20 题) | 2 CRITICAL + 5 MAJOR | ① 打分器用**子串**匹配 → 过短的期望前缀匹配全库 = 结构性满分 (3 题); ② 半数题的期望事实只有字段 ID, 测不出内容正确性; ③ 同标题双卡漏标 (v0 同类缺陷复现); ④ 问句里的某调整因子在 EDC 中**根本不作为项目存在** → 幻觉陷阱 gold 抓不住; ⑤ 覆盖偏科 (两个最大 form 合计占全库 33% 的卡零覆盖) |
| 二轮 (verifier, 验收 5 条件) | 3 MAJOR + 1 PARTIAL | ① 一处 gold 指向**错误的卡族** (早期/晩期观察窗混淆); ② 一处期望事实串是其干扰项的**子串**, 子串匹配下答错也满分; ③ form 级问法却只钉单卡 (该 form 17 卡) = 结构性虚低; ④ "补业务值事实"条件在新增题上整体回归 |

出题人自查另发现 2 项: 一处期望卡指错 (适用症例类别混淆); 一轮审阅引用的某字段**不存在**。
→ **记录: 出题、审题、验收三方各自都有漏网, 三道关缺一不可。**

## 3. 检索侧发现 (pattern 级)

### 3.1 BM25 通道对纯日文查询零信号且方向不稳 (最重要)

`bm25s.tokenize` 按空白/标点切词, **无日文分词**。无空白的日文句被切成**整句一个 token**,
在语料中零匹配; 只有空白分隔的拉丁 token 能幸存:

```python
>>> list(bm25s.tokenize("AE domain の変数を教えてください").vocab)
['ae', 'domain', 'の変数を教えてください']      # 空白区切りの拉丁 token だけ生き残る
>>> list(bm25s.tokenize("この項目はどの画面にありますか").vocab)
['この項目はどの画面にありますか']              # 整句が 1 token → 語彙に一致せず
```

后果: 日文查询下 BM25 返回**近似常量的垃圾集**, 经 RRF 融合挤掉真实 dense 命中。
v1 实测 19 题中 **13 题** top5 混入 0.000 分卡, 且高度集中于**同两张**卡 (13 次 / 12 次)。

**对 v0 记录的修正**: v0 "hybrid 100%" 含出题泄漏成分 —— v0 题目因看卡起草而携带拉丁
标识符 (字段 ID / 版本标签), 恰好喂给 BM25 它唯一能用的 token。
**且 v1.1 下方向再次反转** (hybrid 83.3% > dense 81.3%): 混检净效应随题目措辞分布摆动,
既非稳定增益也非稳定损害 —— 属**未受控变量**。(注: 主库以英文为主但**非纯英文**, 见 §3.1b。)

→ **裁决已做 (2026-08-04): 修分词器, 不关 hybrid** —— 详见 §3.1b。

### 3.1b 裁决与实测: CJK 字符 bigram 切词 (已实装)

选项二取一, 用数据定而非表决:

| 探针 (BM25 **单通道** gold recall, top_k 15) | 结果 |
|---|---|
| 現行切词 | 12.0% (完全命中 2/25, 全 miss 21/25) |
| **CJK 字符 bigram** | **60.9%** (完全命中 13/25, 全 miss 7/25) |

→ 稀疏通道不是对日文无用, 是**切错词**。关掉 hybrid 等于永久放弃一个可达 60.9% 的
独立信号, 故选择修分词器。字符 bigram 为 CJK 检索定式: 无词典、无新依赖、确定性。

**端到端 (study collection, golden v1.1, 25 计分题)**:

| 配置 | source recall | 阈值 85% |
|---|---|---|
| dense-only | 81.3% | FAIL |
| hybrid (原切词) | 83.3% | FAIL |
| **hybrid + CJK bigram** | **88.5%** | **PASS** |

原 miss 的三题 (跨 form 分流 / ID 与语义脱钩长尾卡 / 手术到達法) 转为命中; 新增一处
家族题从 100% 降至 80% (净 +5.2pt)。

**CDISC 英文主库回归验证 (安全属性)**: 变换只作用于 CJK 连续串, 但主库并非纯英文 ——
`VARIABLE_INDEX.md` 含**中文**表头, 66/4146 chunk 会被变换 (中文同样无空白, 方向一致)。
实测 140 题 retrieval-only+hybrid 前后对比:

- **逐题 source_recall 变化: 0 题** (平均值 74.3% → 74.3%)
- top5 召回集变化: 6/140 题 (3 题仅排序, 3 题换掉**非 gold** chunk); 机制为 66 个 chunk
  的切词改变了 BM25 语料级统计量 (avgdl / df), 轻微扰动全局打分 —— 与 gold 命中无关

→ 结论: 对主库**无 recall 回归**; "英文恒等变换"的原始假设不完全成立 (主库含中文),
  但实测影响为零。TDD 8 测试 (含"索引侧与查询侧必须同变换"的接线闸 —— 该测试初版因
  bigram 是原串子串而假绿, 已改为断言空格分隔形态)。

### 3.2 卡片词汇覆盖缺口: form 缩写缺人类可读同义词

一张确定性唯一可答的卡在双配置下恒 miss。根因: 该 form 名在 EDC 中是**缩写**, 卡面
不含该缩写对应的自然语言词; 而另外两个 form 的卡面字面含该词, 故自然问法被拉向后两者。

→ backlog: 卡片渲染写入 form 全称/同义词, 或建 form 级同义词表参与检索。

### 3.3 v1.1 新暴露的三类 miss (dense 配置)

| 形态 | 题数 | 说明 |
|---|---|---|
| **多卡家族只召回其一** | 3 (50%/33%/50%) | 问"是否分成几个项目", 检索只给家族中一张。top_k 内缺多样性 |
| **近义双卡判别失败** | 1 (0%) | 两卡标签与码表取值相同, 区别只在 codelist ID / item group / 显示条件 —— 语义信号极弱 |
| **ID 与语义脱钩的长尾卡** | 1 (0%) | 卡标题与问句近乎逐字重合仍未召回, 语义检索在长尾 form 上的失效样本 |

三类均属 Plan B 结构化直查通道的候选场景 (与丸数字重复组同源)。

### 3.4 卡片渲染残留 HTML 标签

6/959 卡的単位字段含原始 HTML (十余层嵌套 `<span style=...>`), 源自 EDC 导出的富文本,
同时污染检索文本与回答可读性。注: 其中一张正是 §3.1 的 BM25 常量垃圾卡之一 ——
HTML 标签为 BM25 提供了它唯一能切出的拉丁 token。

→ backlog: 卡片渲染层增加 HTML 标签剥离 (与既有换行清洗同层)。

## 4. harness 侧改动 (本轮实装)

`eval/run_eval.py`:
1. 支持 `out_of_scope: true` —— 排除出 recall 平均值 + 单列显示。此前题集注释声称
   "不计入 recall" 而代码对空 expected_sources 照给 1.0, **注释与实现相反比缺功能更危险**。
2. `n_total` 键区分总题数与计分题数 (`n_questions` 语义在过滤后已变)。
3. `avg_src` / `avg_fact` 零除保护。

`server/ja_tokenize.py` (新): CJK 字符 bigram 切词, 接入 `rag.py` BM25 索引与查询两侧。

TDD 14 测试 (harness 6 + 切词 8); 全量 **638 passed** (基线 624 + 14)。

**打分器已知特性 (出题必须知道, 已写进题集头部)**: `check_source_recall` /
`check_fact_recall` 均为**子串**匹配 —— 过短的期望前缀会匹配全库, 期望事实串是干扰项
子串时判别力归零。约定: 期望来源写完整卡片 id 或明确的家族前缀; 期望事实取足够长的唯一串。
