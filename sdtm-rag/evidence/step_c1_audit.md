## 1. 参照物与独立性

参照物完全在生成器之外 —— 不 import `scripts.study.*`, 自己调 poppler CLI:

```bash
PDF=$(.venv/bin/python -c "from scripts.study.paths import resolve_study; print(resolve_study('st01').doc_pdfs[0])")
pdfinfo "$PDF"                                  # Pages: 113, Encrypted: no
for p in $(seq 1 113); do
  pdftotext -layout -f $p -l $p "$PDF" -        # 逐页 → stdout, 拼接为参照全文
done
```

- pdftotext version 26.04.0 (`/opt/homebrew/bin/pdftotext`)
- 参照全文 = 113 页 stdout 顺序拼接, 共 **241,411** 字符 (含换页符)
- 审计脚本: 会话 scratchpad 下 `audit.py` / `extra.py` / `extra2.py` / `extra3.py` (只读 PDF + chunk 文件)
- 生成器代码只**读来理解其声明**, 一切裁定以上面的原始页文本为准
- 本文件自身过了泄漏闸: 逐行取 8 字符窗口比对原文 (含假名/汉字者) 命中 **0**; 研究名 / PDF 文件名 token / 页眉行 (含其任意 6 字符片段) 均不在本文件内

## 2. 抽样方法 (确定性)

1. 文件列表 = `sorted(glob.glob('<docs_dir>/*.md'))` (Python 字节序; 与 shell `ls | sort` 的 locale 序不同, 本报告一律用 Python 序)。
2. 等距网格取 8 个: 索引 `0, 16, 32, 48, 64, 80, 96, 113`。
3. 网格里恰好没有 `__part` 文件, 故**追加**强制样本 1 个: 索引 108 = `8.2` 的第 2/3 份 —— 中间份首尾都无锚点, 是最难的一类。
4. 合计 **N=9**。跨页要求由网格自动满足 (9 个样本中 8 个 `page_start != page_end`)。
5. 另外把同一套三条判据**跑满全集 114 个** (§4.A) —— 抽检成本低到没有理由只抽 9 个。

全集背景: 114 chunk 中跨页 57 个 (50.0%), `__part` 文件 5 个 (2 个家族: `22.1` 2 份 / `8.2` 3 份), 编号 111 个 distinct。

## 4. 全集与结构性核验

### C. 覆盖率 (哪些原文不在任何 chunk 里)

- 全部 chunk 正文按文档顺序拼接 **逐字等于** 参照全文从首锚点起的尾段 (`len diff = 0`) ⇒ 首锚点之后**零丢失、零重复、零错序**。
- 但首锚点**之前** 66,200 字符 (占抽取全文 **27.4%**) 不属于任何 chunk。构成 (只写形态):
  | 页 | 字符 | 形态 |
  |----|------|------|
  | 1–10 | 16,302 | 封面 / 卷首 (无点导, 无编号行) — **实体内容, 未章节化** |
  | 11–16 | 49,320 | 目录 (251 行带点导, 102 行 `n.m` 编号) — 排除合理 |
  | 17 前段 | 578 | 第 1 章标题 + 正文 (该章无 `n.m` 子节) — **实体内容, 未章节化** |
- 最早 chunk = 编号 `2.1` (p17)。章号覆盖 2–14、16–22; **缺 1 与 15**。

### D. 页眉 / 页脚渗入

- 页眉: 一条 **18 字符 ASCII (含数字)** 的同一行, 是全部 113 页的首个非空行。
  - 渗入 **57/114** chunk (恰好是全部跨页 chunk), 共 **96** 次 —— 等于 `Σ(page_end − page_start) = 96`, 即每跨一页带入一条, 无额外渗入, 完全可解释。
  - 其中 **14** 个 chunk 的**末个非空行**就是这条页眉 (判据 ② 形式上通过, 但「末行」是页眉而非内容)。
- 页脚: 109/113 页末行是纯页码行; 共 **103** 条纯数字行渗入 **57** 个 chunk。
- 无跨页 chunk (57 个) 完全不受影响; 首行是页眉的 chunk = 0 个。

### E. 切分位置形态

- **节间切点** (在 `n.m` 标题行前切): 结构上不可能切断句子 —— 切点必在标题行边界。114 个 chunk 末个内容行形态: 句末结尾 54, 页眉 14, 多列 (表格样) 10, 其他 36。
- **`part` 切点** (3 个) 逐个看邻域形态 (T=多列行, .=单列):
  | 切点 | 前 8 行 | 后 8 行 | 判断 |
  |------|--------|--------|------|
  | 8.2 1→2 | `........` | `........` | 纯散文区, 干净 |
  | 8.2 2→3 | `......TT` | `TT......` | 两侧均多列 ⇒ **疑似把一个表格切成两份** |
  | 22.1 1→2 | `.T.T.TTT` | `T.T..T..` | 两侧均多列 ⇒ **疑似把一个表格切成两份** |
  另外 8.2 1→2 的前一份**末行是页眉行**。

### F. 编号归属 (标题层级带来的错标)

- 第 15 章无 `n.m` 子节 ⇒ 其标题 + 正文 (132 字符) 落在标注为 `14.4` 的 chunk 里 (p97)。检索命中这段会被标成 14.4。
- 章标题行归属: 20 个 `N.1` 锚点里, **18 个**的紧前一行是「indent=0、长度 8–25、无句点」的短行 —— 形态与「无编号的章标题行」一致, 而它属于**前一节**的 chunk。即章标题普遍落在上一节 chunk 的尾部。这是 `split_sections.py` 只在二层锚点切分的**已声明设计**的直接后果 (docstring 里写了顶层不可靠), 不属实现缺陷, 但对「按章检索/引用」有影响。

## 6. 总判定

**有条件 PASS。**

- 三条硬判据: **9/9 抽样 + 114/114 全集全过**, 且「首锚点之后拼回逐字等于原文尾段」这一强性质成立 ⇒ 本轨唯一的有损点 (PDF→文本) 之外, **章节化环节零有损**。
- 条件 = 上表 P1/P2/P3/P4 需要作为**显式已知限制**落到文档里 (尤其 P1 的 27.4% 未覆盖 与 P4 的表格被切), 不能默认「切分完备闸绿 = 内容都能检索到」—— 完备闸的口径是「首锚点之后」, 它对 P1 天然免疫。
- 无任何一项构成 FAIL: 没有发现正文被改写、丢失、重复、错序, 也没有文件名泄漏标题。

## 7. 我无法核验 / 未核验的部分 (诚实清单)

1. **PDF 文本层本身是否忠于版面** —— 我的参照物也是 `pdftotext -layout`。若 poppler 在某页丢字、错序、或把表格列错位, 我用同一工具查不出来。要证伪需要人眼比对渲染图或换一个引擎 (如 `pdfplumber` / OCR) 做交叉验证。**这是本报告最大的盲点。**
2. **表格列关系是否在 `-layout` 下保真** —— 我只按「多列空白」形态判断表格, 没有核对任何一格的取值归属。P4 的「疑似切断表格」是形态推断, 未逐格确认。
3. **章标题行的真实性 (P6)** —— 18/20 是按行形态 (indent/长度/无句点) 推断的, 我没有读标题文字去确认 (受零真名约束)。第 15 章 (P5) 是确证的。
4. **`version: V59` 的含义** —— frontmatter 里的 version 字段值我没有溯源到 PDF 或配置, 未核验其正确性。
5. **抽检期间的并发改动 (P7)** —— 抽检开始时读的是 `docs/`, 中途该目录被改名成 `docs_staged/`。我在新路径上把 9 样本 + 全集扫描**完整重跑一遍**, 文件数 (114)、样本文件名、字符数、全部裁定与改名前一致, 故判定为纯改名。但我**没有**在改名前对文件做哈希, 所以「纯改名」是基于上述一致性的推断, 不是哈希级证明。
6. **未核验下游** —— chunk 是否被正确 ingest、embedding 是否覆盖全文 (`8.2` part02 达 15,594 字符, 是否仍在 8191 token 内我没有独立数 token)、检索是否命中, 均在本次范围外。
